Part 0.3: Estimating Camera Pose

In order to recover the camera poses for each image, I will be using Perspective-n-Point. After calibration, I can obtain the its intrinsic matrix and distortion coefficients, which is then used to match each known 3d-corner coordinate to its 2D pixel location. Each pair of correspondences are then passed into cv2.solvePnP to estimate the camera's rotation and translation. Visualizing all the poses together in Viser produces a 3D dome of camera viewpoints, which is displayed below. They are well spread out and covers majority of the angles.

PART 1: Fit a Neural Field to a 2D Image

In this section, I will be fitting the NN onto the test image (fox) and my chosen image (lilies) as displayed below

The general work flow will be trying ot represent a 2D image using a Neural Field. To do so, I will be using the following Model Architecture:

Start: 2D pixel coordinates (x, y)

Positional Encoding: Sinusoidal functions applied to the input cooridnates to expand its dimensionality

2. Batch Size = 10,000
3. Learning Rate = 1e2

PART 2: Fit a Neural Radiance Field from Multi-view Images

2.1: Create Rays from Cameras

Camera to World Coordinates Conversion
I used a simplied version of the matrix equation to implement this part. The w2c contains a rotation matrix and a translation vector, which can be separated. The rotation matrixes are orthonormal and the inverse is just their transpose so the reverse mapping can take the form of $X_w = R^T(X_c -t)$, which is the way my function works for batch and singular points.

Pixel to Camera Coordinate Conversion
For this section, I followed the matrix-vector equation and rearranged it to solve for camera coordinates. Here, we just need to multiply both side by the inverse of K_matrix. Again, I modified it to work for batch and singular coordinates.

Pixel to Ray
We know that a ray can be defined by an origin vector and a direction vector. The origin vector is simply the location in the world, which we can get from a combination of the above 2 functions (Pixel -> camera -> world), with the translation vector (isolated through K) being the camera origin. Then apply the formula described in the specs to find the normalized ray direction, which is the difference between the current world coordinate and r_o divided by the L2 norm of the difference.

2.2: Create Rays from Cameras

Sampling Rays from Images In this section, I chose to write a sampling function that flattens all pixels, and does a global sampling. The main issue here was to get the right index from the image level to the H,W of each image. Sampling rays from images is very similar to part and the samples are all randomly chosen. Here we just need to make sure to add 0.5 so that our pixels are represented by their centers.

Sampling Points along Rays This section invovled a bit more math, where I had to account for perturbance. For just the sampling part, I had to get evenly discretized chunks of the ray before sampling. To do so, I was able to various useful numpy functions to easily like linspace to do so, and then at every chosen point, add a little perturbance (some small random amount) so that every location is touched along the ray.

2.4: Neural Radiance Field

Here we are building a neural network similar to what was done earlier in part 1, but because we are injecting the Positional Encoder, we need to break up the layers. Instead of directly make an nn.sequential, here, I made a class that defined each section (before and after each PE point).

The overall structure of the NN is as follows:

1.input: 3D coordinates (L=10), direction (L=4)

2.first layer: alternating Linear and ReLU layers (input dimension = 60, hidden dimensions = 256)

3.middle layer: similar structure to first layer with PE concatenated so that our model remembers the input features

4.density layer: linear to ReLU that reduces the dimensions from 256 -> 1 and ensure positivity

5.color layer: reduced from 256 -> 3 dimensions for color using Linear, ReLU, and Sigmoid (at the end we get the normalized version)

6.output: density (1D), color (3D)

2.5: Volume Rendering

Since we are getting a density and color for each sample point (as shown by the architecture above), the volume rendering combines them into a final pixel color. At each step, the predicted density and RGB combines to form the color that probably would be seen, and the opacity is dependent on how likely, and we add each contribution to yield the final color. A perfect sum would be infinitesmally small steps, but I will be using the discrete version of the equation.
